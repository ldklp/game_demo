# ForestTable · 可玩原型 v1.1（单人版）

> 一局能从头玩到"逃出森林"的完整流程。
> 用来给美术定风格、给合作者试手感、给外包报价看工作量。

**v1.1 改了两件事**：① 改单人（不再轮流投票）；② 去掉弹窗，改成页面内的步骤流 + "下一步"按钮。

---

## 一、怎么跑起来

**双击 `index.html` 就能玩**，不用装东西、不用服务器、不用联网。

打不开的话（个别浏览器限制本地文件）：

```bash
python -m http.server 8080     # 然后访问 http://localhost:8080
```

---

## 二、现在的一局是什么样

选一个角色 → 进森林 → 走完 4 个阶段即逃出。

**一天 5 回合**（白天 3、夜晚 2），**每回合的流程全部显示在屏幕中央那块面板里，从上往下依次出现**：

```
① 事件    上一回合预告的那张牌开始结算（遭遇敌人 / 神秘事件 / 意外 / 强制）
② 行动    你选：前进 / 收集 / 合成 / 休整
③ 结算    三项属性的变化数字
④ 下一步  → 进入下一回合
```

**每回合只需要 1~2 次点击**（选行动 + 点下一步）。判定骰子会自动滚动，不用点。按 `Enter` 也能推进。

完整一局约 **30 回合**，25–40 分钟。

三条属性同时在掉：**健康**归零进濒死（3 回合内不包扎就死）、**体力**低于 25% 变饥饿、**精神**归零角色自杀。

## 三、v1.1 改了什么（对照 v1.0）

| | v1.0 | v1.1 |
|---|---|---|
| 人数 | 2–4 人同屏热座 | **单人**，一个角色 |
| 决策 | 每人依次投票，平票罚休整 | 你直接决定，没有投票环节 |
| 交互 | 每个环节弹一个模态窗，一回合 5–6 次弹窗 | **页面内步骤流**，内容从上往下追加，不遮挡 |
| 推进 | 点弹窗按钮 | 底部固定的**下一步**按钮（会显示下一张预告的标题） |
| 分食物 | 骰子定序 + 依次取 | 单人简化为"吃几份 / 全吃掉"（多人逻辑仍保留在代码里） |
| 死亡 | 有队友救 | 濒死时只剩一个选项：**包扎伤口**（自救） |

**美术交接不受影响**：图片命名、尺寸、配色变量都没变，见第四节。

## 五、视觉规范

`css/style.css` 顶部 `:root` 集中了全部颜色，**改这十几个变量整个调性就变**：

```css
--bg:#0d1310;   --panel:#151d18;  --line:#27332b;
--ink:#dfe6dd;  --ink-2:#a8b3a6;  --ink-3:#6f7c70;
--accent:#8fb99a;  --accent-2:#5d8a6a;   /* 森林绿 */
--brass:#c9a227;                          /* 黄铜：事件竖线、骰子、天数 */
--danger:#c1573f; --warn:#c98a3f; --good:#6fa87a;
--bar-hp:#b8452f; --bar-st:#c08b3e; --bar-sa:#5f86a8;
--font-serif: "Georgia","Songti SC","SimSun",serif;
```

**字体**：正文系统无衬线，`--font-serif` 用在事件正文、标题、结局——所有文学性的地方靠衬线体撑气氛，买字体优先换这一个。

**当前占位**：物品图标用 emoji（已降饱和），骰子/进度条/状态标签全是 CSS 绘制。图标在 `js/data.js` 的 `FT.ITEMS[x].icon`。

## 六、调数值

全在 `js/data.js` 顶部 `FT.CONFIG`，改完刷新：

```js
TURNS_PER_DAY: 5,         // 一天几回合
DAY_TURNS: 3,             // 前几回合是白天
PROGRESS_GOALS: [6,7,8,9],// 四个阶段的进度阈值 ← 调节奏最有效
ADVANCE_PROGRESS: 3,      // 前进一次加多少
REST_STAMINA: 15, REST_SANITY: 4, REST_HP: 8,
TURN_STAMINA_COST: 3,
DAY_SANITY_COST: 0, NIGHT_SANITY_COST: 2,
SOLO_DAMAGE_MULT: 0.72,   // 单人承受伤害系数（没有队友分担）
```

内容表：`FT.CARDS`（61 张牌）、`FT.ITEMS`、`FT.RECIPES`、`FT.CHARS`、`FT.ENEMIES`、`FT.SCENES`。
卡牌效果语法写在 `data.js` 文件头注释里，照抄格式就能加新卡。

## 七、代码结构

```
web/
├── index.html          入口：标题页（选角色）+ 主界面骨架
├── css/style.css       全部样式
├── js/data.js          全部内容（牌、物品、配方、角色、敌人、场景、配置）
├── js/engine.js        回合状态机、判定、战斗、腐败、存档
├── js/ui.js            渲染 + 舞台面板（stage/ask/dice/foodDivide）
└── assets/             美术放这里
```

**关键接口**：`FT.UI.stage()` 返回一个面板，引擎用它推进整个回合。

```js
const P = FT.UI.stage();
P.head(左, 右)                  // 顶栏
P.section(标签, html)            // 追加一段
P.append(html)                  // 追加裸内容
await P.ask(options, prompt)    // 底部出按钮，等点击
await P.dice({label, mod, dc})  // 内联骰子，自动滚
await P.next('下一步')           // 底部下一步
```

想加新的事件表现方式，只需在 `ui.js` 里给面板加方法，引擎不用改。

## 九、自测

```bash
cd web
node js/_selftest.js 14    # 无头跑整局：通关率 / 平均回合 / 崩溃
node js/_uitest.js         # 渲染冒烟 + 数据引用校验
```

当前基线：**14 局 11 通关，平均 32.6 回合，无运行时错误，模板无脏数据**。
机器人只会"缺什么补什么"，真人会打得更好，所以难度对真人偏低。想更硬可以调小 `PROGRESS_GOALS` 或把 `SOLO_DAMAGE_MULT` 调回 1。
