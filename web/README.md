# ForestTable · 可玩原型 v1.0

> 这不是一张效果图，是一局能从头玩到"逃出森林"的完整流程。
> 用来给美术定风格、给合作者试手感、给外包报价看工作量。

---

## 一、怎么跑起来

**双击 `index.html` 就能玩**，不需要装任何东西、不需要服务器、不需要联网。

如果双击打不开（个别浏览器对本地文件有限制），在文件夹里执行：

```bash
# 任选其一
python -m http.server 8080     # 然后访问 http://localhost:8080
npx serve .
```

推荐 Chrome / Edge / Firefox 最新版。手机浏览器也能玩，但热座投票在手机上体验一般。

---

## 二、这局游戏长什么样

1. 开局选 2–4 人（同屏热座），每人选一个角色：**脚夫 / 猎人 / 卫生员 / 使徒**。
2. 游戏分 **4 个阶段**，每个阶段是一个随机地形：明亮树林 → 阴森树林/河边/沼泽 → 悬崖/瀑布 → 湖畔终点。
3. **一天 5 回合**（白天 3、夜晚 2），每回合：
   - 先结算上一回合抽到、已经亮在桌面上的**预告事件**（遭遇敌人 / 神秘事件 / 意外 / 强制事件）
   - 再由**全体依次投票**决定本回合做一件事：**前进 / 收集 / 合成 / 休整**
4. 进度条走满进入下一阶段；走完第 4 阶段 = 逃出。
5. 三项属性同时掉：**健康**归零进濒死（3 回合没人救就死）、**体力**低于 25% 变饥饿、**精神**归零角色自杀。

完整一局大约 **35 个回合**，40–60 分钟。

### 这版特有的三个交互（最值得看的部分）

| 交互 | 位置 | 为什么重要 |
|---|---|---|
| **依次投票** | 每回合的行动选择、神秘事件抉择 | 一个人投完把设备递给下一个，能看到每个人投给谁都写在结果里 |
| **d20 判定** | 意外事件、脱离战斗 | 转盘式骰子动画 + 成功/失败反馈，是全作最频繁的正反馈点 |
| **分食物** | 休整 → 吃东西 → 选肉汤 | 全员投 d6 定顺序，然后按序取 1~3 份，第二轮反向补。**这碗汤是这个游戏的名场面** |

## 三、目录结构

```
web/
├── index.html          入口（标题页 + 主界面骨架）
├── css/style.css       全部样式；顶部 :root 是配色变量
├── js/data.js          所有内容：61 张事件牌、7 场景、4 角色、9 配方、4 敌人、物品表
├── js/engine.js        回合状态机、判定、战斗、分食、腐败、存档
├── js/ui.js            界面渲染与所有交互（Promise 形式）
├── js/_selftest.js     无头自测：不开浏览器跑完整局，看平衡与崩溃
├── js/_uitest.js       渲染冒烟测试：检查模板有没有输出脏数据
└── assets/             ← 美术只需要碰这个文件夹
    ├── scenes/         场景插画
    ├── chars/          角色立绘
    └── cards/          事件卡面
```

### 4.3 事件卡面 `assets/cards/`

文件名 = 卡牌 ID，例如 `D01.jpg`、`N05.jpg`、`S_BF2.jpg`。
建议 800×450（16:9）。**不必 61 张全画**，优先顺序：

1. 四张遭遇敌人牌：`D01` `D02` `N01` `N08`
2. 三张标志性神秘事件：`D03`（石制祭坛）`D12`（队友的旧物）`S_DF1`（苔藓下的雕像）
3. 其余按卡牌 ID 排下去

完整 ID 清单在 `js/data.js` 的 `FT.CARDS` 里，每张都有 `title` 和 `text` 可当画面描述。

## 五、视觉规范（改这里就能换整体风格）

打开 `css/style.css`，最上面的 `:root` 集中了全部颜色。**改这十几个变量，整个游戏的调性就变了**，不用碰任何结构样式。

```css
--bg:      #0d1310;   /* 页面底色，近黑的墨绿 */
--panel:   #151d18;   /* 卡片底色 */
--line:    #27332b;   /* 描边 */
--ink:     #dfe6dd;   /* 主文字 */
--accent:  #8fb99a;   /* 森林绿：进度、强调、高亮 */
--brass:   #c9a227;   /* 黄铜：标题、预告卡、骰子 */
--danger:  #c1573f;   /* 受伤、失败 */
--bar-hp:  #b8452f;   /* 健康条 */
--bar-st:  #c08b3e;   /* 体力条 */
--bar-sa:  #5f86a8;   /* 精神条（冷色，和另外两条区分开） */
```

**字体**：正文用系统无衬线；`--font-serif` 用在标题、事件 flavour text、结局——所有"文学性"的地方都靠衬线体撑气氛。如果买字体，优先换这一个。

**当前占位素材**：物品图标用 emoji（已做低饱和处理），所有骰子、进度条、状态标签都是纯 CSS 绘制。emoji 是明确的可替换项，见 `js/data.js` 的 `FT.ITEMS[x].icon`。

## 六、策划调数值的入口

全部在 `js/data.js` 顶部 `FT.CONFIG`，改完刷新即可，不用动代码：

```js
TURNS_PER_DAY: 5,        // 一天几回合
DAY_TURNS: 3,            // 前几回合算白天（3 昼 + 2 夜）
PROGRESS_GOALS: [6,7,8,9], // 四个阶段各自的进度阈值 ← 调节奏最有效的旋钮
ADVANCE_PROGRESS: 2,     // 前进一次加多少进度
REST_STAMINA: 15,        // 休整回多少体力
REST_SANITY: 4,          // 休整回多少精神
REST_HP: 5,              // 休整回多少健康
TURN_STAMINA_COST: 3,    // 每回合自然消耗
DAY_SANITY_COST: 0,      // 白天精神消耗
NIGHT_SANITY_COST: 2,    // 夜晚精神消耗（有篝火则减为 1）
```

其余内容表：`FT.CARDS`（事件牌）、`FT.ITEMS`（物品与食物）、`FT.RECIPES`（配方）、`FT.CHARS`（角色）、`FT.ENEMIES`（敌人）、`FT.SCENES`（场景与掉落表）。

卡牌的效果语法写在 `data.js` 文件头注释里，照抄格式就能加新卡。

## 七、当前实现状态

### ✅ 已实现

- 4 阶段完整通关流程、胜/败结局与结算统计
- 61 张事件牌（昼 40 / 夜 21），含遭遇敌人、神秘事件（投票抉择）、意外（d20 判定）、强制跳过行动
- 预告机制：事件提前一回合公开，下一回合结算（含"突袭"立即结算）
- 依次投票 + 平票判定 + 计票可视化（每票记名）
- 四项集体行动：前进 / 收集 / 合成 / 休整
- 九种配方，含烹饪（需篝火）、分食（肉汤 10 份）
- 分食物小游戏：d6 定序 → 依次取 1~3 份 → 反向补第二轮
- 食物回合级保质期，过期自动变"腐败食物"
- 三项属性、饥饿/濒死/流血/中毒/心理疾病/崩溃状态
- 战斗：战/逃抉择、最多 3 轮、武器差异、强光克制未知生命体
- localStorage 自动存档 + 手动导出 JSON + 继续上次存档
- 调试面板（右上 ⚙）：跳到任意场景、回满状态、给材料、直达下一阶段 —— **给美术看全场景用**

### ⏳ 未实现（下一版）

- 个人独立背包（当前为全队共享一格数池，脚夫 +4 格）
- 装备/武器切换界面、投掷物品
- 心理疾病症状的实际效果（幻觉 -1 已生效；偏执、失语只做了记录）
- 联机（房间码 + WebSocket）
- 音效与环境音
- 无尽模式、通关解锁

### 已知简化（有意的取舍）

| 简化 | 原因 |
|---|---|
| 全队共享背包 | 个人背包 + 转交 UI 会增加大量交互，原型阶段先验证「投票是否好玩」 |
| 判定由"该项属性最高的人"自动应对 | 每回合再来一次"谁去判定"的投票会让节奏碎掉，正式版可做成一次快速指认 |
| 战斗自动逐轮结算 | 保留战/逃这个真决策点，把每轮操作省掉；正式版可加"使用道具/掩护队友" |
| 单人模式未做 | 投票机制天然需要多人；调试面板已能支撑一个人走完全流程 |

## 七点五、与计划书 v1.0 的差异（实现时改的）

原型跑起来之后，有几处数值和规则跟文档不一样，理由是"不改就通不了关"。这些都可以在 `FT.CONFIG` 里改回去：

| 项目 | 计划书 | 原型 | 原因 |
|---|---|---|---|
| 休整回复 | 只回体力 | 回体力 + 精神 4 + 健康 5 | 精神原本没有任何恢复渠道，全队会在一周内集体自杀 |
| 白天精神消耗 | -1 | 0 | 同上，夜晚才是精神的主战场，这样篝火才有存在感 |
| 夜晚精神消耗 | -3 | -2（篝火 1） | 12 局测试里 100% 死于精神归零 |
| 中毒 | 持续性，需用药 | 每回合 28% 自愈 | 没有药就是等死，是死循环不是难度 |
| 使徒初始精神 | 40 | 50 | 40 起手活不过第 3 天，卖血流变成送死流 |
| 事件精神惩罚 | 原文数值 | 统一 ×0.6 | 61 张牌里有 50 处精神惩罚，叠起来远超预算 |
| 阶段通过奖励 | 无 | 全队精神 +6 | 给玩家一个"看到新场景"的正反馈 |

另外新增了 `REST_HP` 与热食回精神（烤肉 +3 / 肉汤 +4）——**"吃热的能稳住精神"应该是这个游戏的核心生存逻辑**，文档里漏了。

## 九、拿去给人看的时候，建议这样演示

1. **先玩一遍完整流程**，别只看截图。这游戏的卖点在"投票时四个人看着彼此"，静态图看不出来。
2. 演示分食物时**故意让一个人多拿**，立刻就能看到其他人抗议——这是最好的说服素材。
3. 打开调试面板 `⚙` 跳到"沼泽""瀑布""湖畔"，让美术一次看完 7 个场景。
4. 想给对方看某个具体事件，改 `js/data.js` 里 `FT.CARDS` 的顺序没用（是随机抽的）——直接让他在游戏里多玩两回合，或者临时把 `drawCard()` 改成固定返回某张。
